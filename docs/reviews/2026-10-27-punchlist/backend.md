## Checked and fine

- **Fuzzing:** I sent 1,258 requests over every `/api/*` route in the OpenAPI spec: no body, `{}`, `[]`, a bare string, bad JSON, null fields, schema-valid bodies, oversize values and empty values, with path IDs of abc/-1/999999/1. The only 500s are the integer-overflow cases and the support/discovery case listed above. Everything else returned 2xx/4xx.
- **Generic `/api/data` round trip:** POST/PUT/GET for all 31 `MODEL_MAP` types with valid values, including ISO date strings on DateTime columns, saved and read back without error. Singletons (`funeral_data`, `advanced_assets`, `digital_guardian`) upsert to one row.
- **Production-mode behaviour (local, SQLite):**
  - HTTP→HTTPS 301 redirect, with the health check exempt.
  - CSRF double-submit is enforced with 403 `CSRF_FAILED` on protected writes, and the frontend fetch wrapper adds the header for every same-origin write (`hooks.client.ts`).
  - The CSRF cookie is `Secure; SameSite=lax; Max-Age=3600`. HSTS is present.
  - `_technical` is stripped from error bodies.
  - CORS rejects non-whitelisted origins (production `CORS_ORIGINS` is the two continuum.estate origins).
  - Passkey login challenges are single-use: a replay returns 400.
  - Startup prints configuration warnings only and blocks nothing.
- **Other checks:**
  - The rate limiter keys on Railway's `X-Real-IP`. The Procfile/nixpacks start command passes `--proxy-headers --forwarded-allow-ips=100.64.0.0/10`.
  - `GET /api/pulse/settings` does not write.
  - Media `only_if_unused` removes an unreferenced file on a clean account. It keeps the file when 65 or more candidate rows exist, which is conservative by design.
  - Access tokens reject typed (magic-link) JWTs. Magic links are one-time.
  - Admin routes require `is_admin`. `/api/admin/users` is paginated (limit ≤ 100).
  - Owner-scoped routers all check `user_id` before returning or changing rows. I found no cross-user read or write, apart from #20.
  - The export snapshot runs one SELECT per table with in-memory attachment matching, so there is no N+1. The scheduler loops per user, which is acceptable at this scale.
