## Verdicts

### A — Confirmed P1: a late request or auth result crosses an account boundary

**Primary:** CONTRACTS; related SHELL and MEDIA observations should be grouped by root cause.

**Plan contracts:** X24 (refresh/retry), X54/X56 (session initialization and account switching), X62 (stop A's pending work from reaching B).

The fetch wrapper waits for the original response at `frontend/src/hooks.client.ts:79`. On a 401, it reads the token currently in localStorage at line 95. When B has signed in while A's request was pending, B's token differs from A's `Authorization` header. The condition at line 96 is false, so it skips refresh and substitutes B's token at lines 108–109 while preserving the original URL, method and body. For a write, this can send A's record payload into B's estate. SyncManager's captured-token checks cannot prevent a write replay performed inside this lower-level wrapper.

Two companion paths have the same missing session-identity guard:

- `frontend/src/lib/stores/auth.ts:65–78` captures a refresh token, awaits its response and stores the returned tokens without confirming that the initiating session is still current. A late A refresh can overwrite B's stored credentials.
- `frontend/src/lib/stores/auth.ts:124–133` accepts a late `/me` result, registers that account's preference namespace and updates the auth store without checking whether logout or another login occurred during the request. `initRun` only guards the later bookkeeping at lines 164–167, after `loadSession` has already mutated the store.

**Recommendation:** bind refresh, request retry and auth-result application to a session/account generation. A token changing within the same session may permit refresh retry; a session/account replacement must cancel or ignore the old result. Scope shared refresh promises to that generation.

**Acceptance:** delay A's write/refresh/`/me` result, switch to B, release the old response, and verify zero A writes, credentials, user state or preference namespace are applied to B. Same-account token refresh must still retry once successfully.

**Evidence level:** source-confirmed; this independent reviewer did not rerun the contracts reviewer's synthetic proof.

### B — Confirmed P1: downloaded PDFs destroy text outside Latin-1

**Primary:** HANDOVER; LEGACY's standalone-letter observation is the same defect family.

**Plan contracts:** D1 (full text and correct names agree across outputs), C3 (letter text preserved), X110 (owner/recipient names), U50 (subscription letter PDF reflects the letter).

`frontend/src/lib/services/exportService.ts:709–711` replaces every character outside `U+0000–U+00FF` (apart from newlines) with `?`; `packetPDF` applies it to every written string at line 734. The cover owner/executor names, record titles and full letter/story fields therefore lose Hebrew, Cyrillic and many other names/words, although the HTML packet retains the source strings.

The same destructive replacement exists in the user-facing standalone downloads:

- `frontend/src/routes/modules/letters/+page.svelte:213–218` replaces characters at line 215 before rendering the entire letter.
- `frontend/src/routes/modules/subscriptions/+page.svelte:330–338` replaces characters at line 332 before rendering the cancellation letter.

This is a data-fidelity gap in an existing export capability, rather than a request to translate the product. A saved name or author's words need not be English to require preservation.

**Recommendation:** use a shared Unicode-capable PDF rendering path with suitable font coverage and shaping/bidirectional handling where needed. Preserve the stored prose and names exactly, instead of replacing unsupported characters.

**Acceptance:** export representative accented Latin, Hebrew and Cyrillic names and long prose through the packet, standalone letter and cancellation-letter paths; compare text and visually verify the PDFs against their source/HTML. Include mixed direction text and page wrapping.

**Evidence level:** source-confirmed. No PDF was generated by this independent reviewer; HANDOVER/LEGACY own any additional proof.

### C — Confirmed P1: an old Try Again action can save a different draft

**Primary:** FINANCES; coordinate other modules using the same mutable callback pattern.

**Plan contracts:** B4/B4.1/B4.2 (failed-save draft retention and meaningful retry), X136 (property's already-implemented immutable pending-save precedent).

`frontend/src/lib/services/sync.svelte.ts:440–444` stores the caller's `onRetry` callback when a create fails. The callback is not bound to the original payload by the manager. `frontend/src/lib/stores/notificationStore.ts:59–66` retains it in the error notification until dismissal; errors have no corresponding automatic expiration. Several live callers pass functions that read the current mutable form:

- Financial accounts: `frontend/src/lib/components/archetypes/AssetManager.svelte:310` passes `saveAsset`; `resetForm` clears/replaces the draft at lines 356–378.
- Subscriptions: `frontend/src/routes/modules/subscriptions/+page.svelte:174` passes `saveSubscription`; lines 199–214 reset the form.
- Insurance: `frontend/src/routes/modules/insurance/+page.svelte:360–362` passes `handleAddPolicy`; lines 279–298 reset the form and editing mode.
- Medical directives: `frontend/src/routes/modules/medical/+page.svelte:151–153` passes `saveDirective`; lines 214–233 close/reset the form and discard an unsaved attachment through `dropUnsavedFile`.

After Draft A's create fails, closing/resetting the form and starting Draft B leaves A's error notification alive. Its Try Again now calls the save function against B's current fields. The action no longer retries the record that failed and may save a new unintended record; the original fields/medical attachment are not retained for that retry. Keeping A's modal open in the immediate proof does not cover this transition.

**Recommendation:** retain an immutable pending operation including its payload, draft identity and required media, or explicitly invalidate the old retry when that operation is abandoned. Prevent an old callback from acting on another draft; ensure success resets only its own form.

**Acceptance:** force A's create to fail, close the form, open/edit B, invoke A's Try Again, and verify the defined original-operation behavior with no B save or duplicate. Cover attachment retention and user retry plus form-save races. FINANCES reports an inline synthetic subscription proof whose attempted names were `Draft A`, then `Draft B`; this reviewer has not rerun it.

**Evidence level:** independently source-confirmed; synthetic runtime evidence belongs to FINANCES.
